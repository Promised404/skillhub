# 完整指南

本指南涵盖 Skill 开发者和团队管理员两大角色的完整使用说明。

---

# 第一部分：Skill 开发者

## 1. 认识 SkillHub

SkillHub 是公司的**技能商店**。你可以把它理解为「AI 助手的应用商店」：

- **Skill（技能）**：一段可复用的工作流或知识，打包后可以被 AI 助手（如 OpenClaw / WorkBuddy）加载和使用
- **SkillHub**：集中存放、搜索、分发这些技能的地方

公司里三类角色：

| 角色 | 做什么 |
|------|--------|
| Skill 开发者 | 创建和发布 Skill |
| 团队管理员 | 管理团队成员、审核 Skill |
| 平台管理员 | 管理整个 SkillHub 平台 |

大多数同学是前两种角色的叠加——既写 Skill，也管自己团队的 Skill。

## 2. 登录与账号

### OMS 登录

1. 打开 [SkillHub](https://skillhub.fr24.ai)
2. 点击登录，使用公司 OMS 账号完成认证
3. 首次登录后会自动创建账号

### 获取 API Token

API Token 是 OpenClaw / WorkBuddy 访问 SkillHub 的凭证，登录网页用的是 OMS，但 AI 助手需要 Token。

1. 登录 SkillHub，点击右上角头像 → **Settings**
2. 进入 **API Tokens** 页面
3. 点击 **Create Token**
4. 填写名称（如"日常使用"或"CI 自动发布"），选择有效期
5. 复制生成的 Token

::: warning
Token 只在创建时显示一次，请立即保存到安全的地方。不要把 Token 提交到代码仓库或发给他人。
:::

## 3. 用 OpenClaw / WorkBuddy 操作 SkillHub（推荐方式）

安装 **fr24-skillhub** 技能后，你可以直接用自然语言操作 SkillHub，不需要记命令。

### 安装 fr24-skillhub

对 AI 助手（OpenClaw / WorkBuddy）说：

> 帮我安装 fr24-skillhub 技能，使用 registry https://skillhub.fr24.ai，版本 latest

AI 助手会自动完成安装，你不需要自己操作终端。

### 登录

首次使用时，系统会检测到未登录，并提示你提供 Token。你只需说：

> 用这个 token 登录公司 SkillHub：`sk_xxxxx`

系统会自动验证 Token、保存凭证，之后所有操作都无缝进行。

### 日常操作话术手册

| 你想做什么 | 对 AI 助手说 |
|-----------|---------------|
| 看看公司有哪些 Skill | "查一下公司有哪些 skill" |
| 搜索某个主题的 Skill | "找一下和周报相关的 skill" |
| 查看某个 Skill 的详情 | "看看 daily-report 这个 skill 是做什么的" |
| 安装一个 Skill | "安装 daily-report 这个 skill" |
| 更新已安装的 Skill | "更新 daily-report 这个 skill" |
| 发布一个 Skill | "把这个 skill 发布到公司 SkillHub" |

### 发布前的确认机制

发布是影响其他人的操作，所以 AI 助手在执行前会向你确认以下信息：

- **目标地址**：永远是 `https://skillhub.fr24.ai`（公司私有部署）
- **目标团队**：你要发布到哪个团队空间
- **Skill 名称和描述**：从你的 SKILL.md 中读取
- **版本号**：你希望标记的版本（如 1.0.0）
- **可见性**：公开（所有人可见）/ 团队内（仅团队成员可见）/ 私有（仅自己可见）

你确认后才会执行发布。如果信息有误，可以随时修正。

### 常见问题

**提示"还没登录公司 SkillHub"**

说明 Token 未配置或已过期。打开 [SkillHub](https://skillhub.fr24.ai) → Settings → API Tokens，创建新 Token，然后对 AI 助手说"用这个 token 登录公司 SkillHub：`sk_xxxxx`"。

**执行搜索/安装时出错**

可能的原因：
- Token 过期：重新创建并登录
- 网络问题：确认能访问 `https://skillhub.fr24.ai`

## 4. 创建你的第一个 Skill

### SKILL.md 是什么

每个 Skill 的根目录必须有一个 `SKILL.md` 文件。它是这个技能的"身份证"，告诉 SkillHub 和 AI 助手这个技能叫什么、做什么、怎么用。

SKILL.md 的顶部是 **frontmatter**（用 `---` 包围的 YAML 区域），写下基本信息；后面是正文，写技能的详细内容和使用说明。

### frontmatter 字段说明

| 字段 | 是否必填 | 说明 | 示例 |
|------|---------|------|------|
| `name` | 必填 | 技能名称，英文小写加横线 | `daily-report` |
| `description` | 必填 | 一句话描述技能用途 | `生成每日工作日报` |
| `version` | 选填 | 技能版本号（语义化版本） | `1.0.0` |
| `license` | 选填 | 开源协议 | `MIT-0` |

### 最小模板

```markdown
---
name: my-skill
description: 一句话说清楚这个技能是干什么的
---

# 我的技能

这里写技能的详细内容。
```

### 完整示例

下面是一个「日报生成」技能的完整 SKILL.md：

```markdown
---
name: daily-report
description: 根据今天的工作内容，生成格式化的日报
version: 1.0.0
license: MIT-0
---

# 日报生成技能

## 用途

帮助员工快速生成每日工作日报，格式符合公司模板要求。

## 使用方式

对我说："帮我写今天的日报"，然后告诉我今天做了什么。

## 格式要求

日报包含以下部分：
- 今日完成事项
- 明日计划
- 需要协调的问题
```

### 目录结构

除了 SKILL.md，你还可以在目录中放入其他辅助文件：

```
daily-report/
├── SKILL.md              # 必须，技能描述文件
├── scripts/              # 可选，脚本文件
│   └── generate.sh
├── templates/            # 可选，模板文件
│   └── report.md
└── examples/             # 可选，使用示例
    └── sample-output.md
```

### 文件限制

| 限制项 | 值 |
|-------|-----|
| 单个文件大小 | 最大 10MB |
| 整个包大小 | 最大 100MB |
| 文件数量 | 最多 500 个 |
| 允许的文件类型 | `.md`, `.txt`, `.json`, `.yaml`, `.yml`, `.js`, `.ts`, `.py`, `.sh`, `.png`, `.jpg`, `.svg` 等 50+ 种 |

## 5. 发布 Skill

### 方式一：通过 AI 助手（推荐）

1. 确保你的 Skill 目录下有 `SKILL.md`
2. 对 OpenClaw 或 WorkBuddy 说：

> 把这个 skill 发布到公司 SkillHub

3. AI 助手会展示确认信息，包括：
   - 目标地址：`https://skillhub.fr24.ai`
   - 可选的团队列表（会自动查询你加入的团队）
   - Skill 名称和描述
   - 版本号
   - 可见性默认值：公共空间 → 公开，团队空间 → 团队内
4. 确认无误后，AI 助手执行发布

### 方式二：通过网页

1. 登录 [SkillHub](https://skillhub.fr24.ai)
2. 点击 **Dashboard** → **发布**
3. 选择要发布到的团队
4. 上传 Skill 包（zip 格式）或选择文件
5. 填写版本说明
6. 点击 **发布**

### 发布后的状态

| 状态 | 含义 |
|------|------|
| 待审核 | 需要团队管理员或平台管理员审核后才能正式发布 |
| 已发布 | 审核通过，所有人（或团队内成员）可以搜索和安装 |

平台管理员发布时会跳过审核，直接变为「已发布」。普通成员发布需要等审核。

### 选择发布到哪里

| 空间 | 适合场景 | 默认可见性 |
|------|---------|-----------|
| 公共空间（`@global`） | 全公司通用的技能 | 公开 |
| 团队空间（如 `@data-team`） | 只有你们团队用的技能 | 团队内 |
| 私有 | 仅自己可见 | 私有 |

如果不确定选哪个，先发到团队空间，后续可以申请推广到公共空间。

## 7. 实践案例

下面几个案例基于公司线上站点 [https://skillhub.fr24.ai](https://skillhub.fr24.ai) 的真实使用方式。你可以先照着跑一遍，再把 Skill 名称和团队空间换成自己的。

### Case 1：给 AI 助手接入公司私有 SkillHub

适合对象：第一次使用公司 SkillHub 的同学。

目标：安装 `@global/fr24-skillhub`，让 AI 助手以后都使用公司私有 registry，而不是公共 ClawHub。

对 AI 助手说：

> 帮我安装公司 SkillHub 助手 fr24-skillhub，使用 registry https://skillhub.fr24.ai，版本 latest

网页确认：

1. 打开 [SkillHub](https://skillhub.fr24.ai)
2. 在热门下载或搜索结果中打开 `fr24-skillhub`
3. 详情页右侧会显示安装命令，你也可以复制这条命令让 AI 助手执行

安装后，用 API Token 登录：

> 用这个 token 登录公司 SkillHub：`sk_xxxxx`

验收方式：

> 查一下公司最近发布了哪些 skill

如果能搜到 `fr24-skillhub` 或 `fr24-ai`，说明公司 registry 已经接通。

### Case 2：安装航班/机票业务 Skill

适合对象：需要处理 Flightroutes24 航线、机票搜索、校验或生单流程的业务同学。

目标：找到并安装线上已经发布的 `@global/fr24-ai`。

网页操作：

1. 打开 [SkillHub](https://skillhub.fr24.ai)
2. 在首页搜索框输入 `fr24-ai`，或点击 **探索技能** 后搜索 `机票`
3. 打开 `fr24-ai` 详情页，查看描述和版本
4. 查看详情页描述和版本，或让 AI 助手代为安装

AI 助手话术：

> 找一下和机票、航班相关的 skill

> 安装 fr24-ai 这个 skill

使用时可以直接说：

> 查一下明天上海到曼谷的航班

> 帮我校验这个机票订单信息

> 根据这组乘机人信息生单

验收方式：AI 助手能识别 `查航班`、`搜机票`、`预订`、`生单`、`飞` 等触发词，并进入对应业务流程。

### Case 3：把团队沉淀的 SOP 发布成 Skill

适合对象：希望把重复流程沉淀给团队复用的开发者、运营或产品同学。

场景示例：客服团队把“航班变更通知”处理 SOP 做成 `flight-change-notice`。

本地目录：

```text
flight-change-notice/
├── SKILL.md
├── templates/
│   └── notice.md
└── examples/
    └── delayed-flight.md
```

`SKILL.md` 示例：

```markdown
---
name: flight-change-notice
description: 根据航班变更信息生成中文客户通知，并检查是否缺少关键字段
version: 1.0.0
---

# 航班变更通知

当用户提供航班号、原起飞时间、新起飞时间、原因和乘客语言偏好时，生成客服可直接发送的通知文案。

## 输出要求

- 先列出缺失字段
- 再生成中文通知
- 语气礼貌、简洁，不承诺未确认的赔付
```

发布话术：

> 把当前目录的 skill 发布到公司 SkillHub，发布到客服团队空间，版本号 1.0.0

发布前检查：

| 检查项 | 建议 |
|--------|------|
| 命名空间 | 团队内部 SOP 先发布到团队空间，不要直接放 `@global` |
| 可见性 | 团队流程优先选择团队内可见 |
| 敏感信息 | 示例文件不要包含真实客户姓名、手机号、证件号、订单号 |
| 版本说明 | 写清楚本次支持哪些场景，方便审核 |

发布后如果进入「待审核」，通知团队管理员在 Dashboard 的待审核列表中处理。

### Case 4：团队管理员审核一个新 Skill

适合对象：团队 Owner 或 Admin。

场景：团队成员提交了 `flight-change-notice`，需要确认能否发布。

审核步骤：

1. 登录 [SkillHub](https://skillhub.fr24.ai)
2. 进入 **Dashboard** → **待审核**
3. 打开待审核 Skill，先看描述是否清楚、版本号是否合理
4. 切到「文件」查看 `SKILL.md`、模板和示例
5. 查看「安全审计」结果，确认没有密钥、个人信息或危险脚本
6. 通过审核，或驳回并写明修改建议

常见驳回原因：

| 问题 | 驳回建议 |
|------|----------|
| 描述太泛 | 补充适用场景、输入和输出要求 |
| 示例包含真实数据 | 替换成脱敏样例 |
| 脚本会访问外部服务 | 说明访问目的、配置方式和失败处理 |
| 发布到了公共空间 | 先发布到团队空间，稳定后再申请推广 |

### Case 5：给 CI/CD 创建自动发布 Token

适合对象：维护一批 Skill，并希望通过流水线自动发布的团队。

推荐做法：

1. 登录 SkillHub → **Settings** → **API Tokens**
2. 创建名为 `客服团队 Skill CI` 的 Token
3. 有效期选择一个明确周期，例如 90 天或 180 天
4. 把 Token 存到 CI 平台的密钥管理中，不要写进仓库
5. 流水线中设置 registry 和 token：

```bash
export SKILLHUB_REGISTRY=https://skillhub.fr24.ai
export SKILLHUB_TOKEN=sk_xxxxx

skillhub publish ./flight-change-notice --namespace customer-service --visibility namespace-only
```

上线前检查：

| 检查项 | 为什么 |
|--------|--------|
| Token 独立创建 | 泄露后可以单独撤销，不影响个人日常使用 |
| Token 名称清楚 | 管理员能看懂用途 |
| 不使用永不过期 | 降低长期泄露风险 |
| 发布到固定 namespace | 避免流水线误发到公共空间 |

## 8. 版本管理

### 版本号规则

版本号采用 **语义化版本**格式：`主版本.次版本.修订版本`，例如 `1.2.3`。

通俗理解：
- **主版本**（左边）：做了不兼容的大变动才加，比如完全重写了技能
- **次版本**（中间）：加了新功能但向后兼容，比如新增了一个输出格式
- **修订版本**（右边）：修了个小 bug 或小调整

小修改直接递增修订版本就好；新功能递增次版本。

### 发布新版本

修改文件后重新发布即可，版本号需要比上一次发布的版本号更高。

通过 AI 助手：

> 发布这个 skill 的新版本，版本号 1.1.0

通过网页：进入 Skill 详情页 → 点击「发布新版本」→ 上传新版文件 → 填写版本说明。

### 版本对比

在 Skill 详情页，你可以选择任意两个版本进行对比，查看文件差异。这在确认改动内容时很有用。

### Yank（撤回）错误版本

如果发现已发布的版本有严重问题，可以 Yank 它。Yank 后这个版本仍然存在，但不会被默认安装（相当于标记为"不要用"）。

在 Skill 详情页 → 版本列表 → 对应版本的「撤回」按钮。

## 9. 其他实用功能

### 收藏

# 第二部分：团队管理员

## 10. 团队管理入门

### 什么是团队

**团队**（技术名称：namespace）是 SkillHub 中组织人员和 Skill 的基本单元。每个团队有自己的空间，团队内的 Skill 默认只有成员才能看到和使用。

举个例子：
- `@data-team` — 数据团队的空间，里面放着数据分析相关的 Skill
- `@ops-team` — 运维团队的空间，里面放着运维自动化相关的 Skill
- `@global` — 公共空间，全公司都能看到

### 管理员做什么

作为团队管理员，你的日常工作是：
- **管人**：添加/移除成员，分配角色
- **管 Skill**：审核新发布的 Skill，处理举报
- **管安全**：关注安全扫描结果，必要时下架有问题的 Skill

## 11. 创建与管理团队

### 创建团队

1. 登录 SkillHub → Dashboard → **我的团队** → **创建团队**
2. 填写团队名称和标识（slug，如 `data-team`）
3. 创建成功后你自动成为团队负责人

### 团队状态

| 状态 | 含义 | 什么时候用 |
|------|------|-----------|
| 正常 | 团队运转正常，成员可以正常发布和使用 Skill | 默认状态 |
| 冻结 | 团队被暂停，成员无法发布新 Skill | 团队出现违规或需要整顿时 |
| 归档 | 团队已停用，Skill 只读 | 团队解散或合并后 |

冻结和归档的区别：冻结算"暂停"，解冻后可以恢复；归档是"结束"，一般不会再恢复。

## 12. 成员与权限管理

### 三种角色

| 角色 | 能做什么 | 通俗理解 |
|------|---------|---------|
| 负责人（Owner） | 一切操作，包括转让团队、删除团队 | 团队所有者 |
| 管理员（Admin） | 管理成员、审核 Skill、修改团队设置 | 大管家 |
| 成员（Member） | 发布 Skill、使用团队 Skill | 普通成员 |

关键区别：
- 负责人可以转让团队所有权，管理员不行
- 管理员不能修改负责人的角色
- 成员可以发布 Skill，但需要管理员审核

### 添加成员

1. 进入团队详情页 → **成员管理**
2. 点击 **添加成员**
3. 输入对方的用户名或姓名搜索
4. 选择角色，点击确认

### 修改角色

在成员列表中，点击成员旁边的角色标签即可修改。注意不能修改负责人的角色（除非你是负责人并在转让所有权）。

### 移除成员

在成员列表中，点击对应成员的移除按钮。移除后对方不再能看到团队内的 Skill（除非 Skill 设为公开）。

## 13. 审核 Skill

### 谁需要审核

当团队成员发布 Skill 时，如果开启了审核流程，Skill 会先进入「待审核」状态，需要管理员手动审核。

| 发布者 | 审核要求 |
|--------|---------|
| 普通成员 | 需要管理员审核 |
| 团队管理员 | 直接发布（无需审核） |
| 平台管理员 | 直接发布（无需审核） |

### 审核操作

1. Dashboard → **待审核**（或在团队详情页的审核列表）
2. 查看 Skill 详情，包括文件内容、安全扫描结果
3. 选择操作：
   - **通过**：Skill 正式发布，所有人（或团队内）可以搜索和安装
   - **驳回**：填写驳回原因，通知发布者修改后重新提交

### 审核流程说明

SkillHub 有两层审核：

| 层级 | 审核者 | 作用 |
|------|--------|------|
| 团队层 | 团队管理员 | 把关技能质量和安全性 |
| 平台层 | 平台管理员 | 把关公共空间的技能质量 |

发布到团队空间只需要团队管理员审核即可；发布到公共空间还需要平台管理员审核。

## 14. 安全扫描与治理

### 查看扫描结果

每次发布 Skill 时，SkillHub 会自动进行安全扫描。在 Skill 详情页的「安全审计」标签下可以看到扫描结果。

扫描结果用三种颜色标识：

| 颜色 | 含义 | 建议 |
|------|------|------|
| 红色（严重） | 发现高风险问题（如恶意代码、敏感信息泄露） | 不应发布，联系发布者修复 |
| 黄色（警告） | 存在中等风险（如依赖漏洞） | 建议修复后再发布 |
| 绿色（安全） | 未发现问题 | 可以放心发布 |

### 下架 / 隐藏 / 归档

当 Skill 出现严重安全问题时，管理员可以采取以下操作：

| 操作 | 效果 | 适用场景 |
|------|------|---------|
| 隐藏 | Skill 不再出现在搜索结果中，但已安装的仍可使用 | 暂时屏蔽，等修复后恢复 |
| 下架（Yank） | 标记为不可用，新安装不会获取此版本 | 发现 bug，阻止新用户安装 |
| 归档 | Skill 整体变为只读 | Skill 已过时，不再维护 |

### 处理举报

成员可以举报有问题的 Skill。管理员在 Dashboard → **举报** 中查看举报列表，处理后回复举报者。

## 15. 推广 Skill

### 什么是推广

团队内的优质 Skill 可以申请推广到公共空间（`@global`），让全公司的人都能搜索到。

### 推广流程

1. 在 Skill 详情页点击 **申请推广**
2. 填写推广理由
3. 平台管理员审核通过后，Skill 会同步到公共空间

推广不会移动 Skill，只是在公共空间创建一个引用，原始 Skill 仍在团队空间中管理。

## 16. API Token 与自动化

### 创建 Token 用于 CI/CD

如果你需要在 CI/CD 流水线中自动发布 Skill，可以为流水线单独创建一个 Token：

1. SkillHub → Settings → **API Tokens** → 创建 Token
2. 名称建议写清楚用途，如 "data-team CI 发布"
3. 有效期根据需要选择，建议不要选"永不过期"

### 在流水线中使用

```bash
# 设置环境变量
export SKILLHUB_REGISTRY=https://skillhub.fr24.ai
export SKILLHUB_TOKEN=sk_xxxxx

# 发布
skillhub publish ./my-skill --namespace data-team --visibility namespace-only
```

### 安全注意事项

- **不要把 Token 硬编码在代码里**，使用 CI 平台的密钥管理功能（如 GitHub Secrets）
- **不要使用别人的 Token**，每个流水线用独立的 Token，方便随时撤销
- **Token 泄露后立即撤销**：Settings → API Tokens → 对应 Token 的删除按钮
- **定期轮换 Token**，不要一个 Token 用到天荒地老
